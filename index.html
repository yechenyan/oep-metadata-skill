        One copy of the evidence

        Metadata, profile, background text, constraints, snapshots and hashes are preserved. Duplicate profile evidence points to context.profile; review-only lists and internal guards remain available in the full context.

        Acceptance and delivery still validate

        record-metadata checks the document, evidence and bindings before acceptance. deliver checks again. A separate check is available for diagnostics; independent combined review still needs a current conflict-free assessment.

        The AI can query a field with schema --pointer or inspect --view full when needed. Unknown facts remain unknown. Mechanical validity and these small tests do not prove factual correctness for every dataset.

        Review results / read by category

        A reviewed field is not necessarily a problem.

        Start with conflicts and unresolved questions. Evidence-supported and not-applicable decisions are recorded separately so they do not inflate the issue list.

        Illustrative example: one field in each category. Actual counts are computed from the review, not from this demonstration.

        conflict Conflicts - inspect or correct

        Evidence contradicts the current value. Inspect the finding, evidence and proposed replacement.

        /resources/0/schema/fields/3/unit
        Example: the value is GW, while the source declares TWh. A proposed replacement is TWh.

        unknown Unresolved - needs evidence

        There is not enough evidence to confirm the value. This is not a confirmed error; provide a declaration or retain uncertainty.

        /resources/0/schema/fields/0/nullable
        Example: no nulls were observed, but no non-null constraint was declared.

        supported Evidence-supported - expand to inspect

        Available evidence supports the current value within the reviewed scope. Usually no action is needed.

        /resources/0/schema/fields/1/description
        Example: the alpha-3 description agrees with the codebook and observed country codes.

        not_applicable Not applicable - expand to inspect

        The concept does not apply, with a stated reason. Missing evidence alone does not establish inapplicability.

        /resources/0/context/grantNo
        Example: an authoritative declaration confirms there was no grant funding, so a grant number is not applicable.

        A correction and a new review are separate steps

        Illustrative example; these counts are not a live run.

        1. Original review.md1 conflict · 1 unknown
        2. metadata.suggested.jsonDocumented unit corrected

        The old report keeps its original findings. A fresh review can clear the corrected conflict; an unsupported license or date still needs evidence.

        These are decision categories, not severity scores. Program checks appear directly in review.md. Read summary.md for grouped actions; there is no separate validation or question JSON to interpret.

        A division of responsibilities

        The AI drives the task. Tools check its work.

        You set the scope.

        Choose the inputs and target, supply missing facts, inspect the results, and authorize a specific remote action when needed. A local draft does not authorize upload.

        The host AI leads.

        The AI reads, asks, writes, checks, repairs and decides when to deliver. It coordinates any fresh independent Reviewer; Python tools do not call a model or choose roles.

        Python binds and checks.

        Snapshots, hashes and validation gates make accepted results traceable. Tool responses inform the AI; they do not schedule a workflow or prove factual correctness.

        Read the outcome, not just the badge. Generated metadata must pass checks before delivery. If honest completion is impossible, the AI stops with a concise explanation. OEP uploads need verified readback; production writes remain unverified by this project.
